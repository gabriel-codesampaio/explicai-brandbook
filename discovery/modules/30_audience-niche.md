## Synthesis

### Perfil (ICP)

Quem **constrói ou mantém software e precisa entregar manual**, sem ter um time de documentação dedicado. Três formas do mesmo perfil, com o mesmo peso:

| Perfil | Situação típica |
|---|---|
| Dev solo / equipe pequena de SaaS | Lançou o sistema, o manual ficou para depois |
| Software house | O contrato pede manual na entrega |
| Redator técnico / analista de suporte | A tela mudou e o manual tem que ser refeito |

### Gatilhos que a comunicação deve nomear

1. **Lançar:** "o sistema vai para o ar e o manual ainda não existe".
2. **Entregar:** "o cliente quer o manual junto com o sistema".
3. **Atualizar:** "a tela mudou e o manual ficou velho". Pede recurso de atualização fácil e, no futuro, checagem automática.

O suporte sobrecarregado é consequência, não gatilho. Vale usar como argumento ("menos chamado repetido"), não como porta de entrada.

### Idioma

Bilíngue desde o primeiro dia: app, README e site em PT-BR e EN. O blog codesampa.io segue em português.
Implicação para a marca: "Explicaí" precisa funcionar para quem não fala português. Slogan e descrição curta precisam de versão em inglês. A pronúncia ("ex-pli-ka-EE") deve aparecer no README em inglês.
