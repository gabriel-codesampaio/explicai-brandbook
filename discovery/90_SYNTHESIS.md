## 1. Núcleo

| | |
|---|---|
| **Propósito** | Documentar um sistema não pode custar mais que construí-lo. |
| **Frase-resumo (interna)** | O Explicaí é o construtor de manuais aberto que deixa a documentação andar no ritmo do código. |
| **Slogan** | Tira o print, que o Explicaí explica. *(em português nas duas línguas)* |
| **Categoria** | Construtor de manuais |
| **Diferencial principal** | Open source e gratuito |

## 2. Posicionamento

> Para devs e software houses que precisam entregar manual sem parar o desenvolvimento, o Explicaí é o construtor de manuais open source e gratuito que vai do print ao manual pronto em PDF, HTML e Markdown.

**Hierarquia de mensagem**
1. Open source e gratuito
2. Do print ao manual pronto (o print colado, a marcação na imagem, os passos escritos)
3. Sai em PDF, HTML e Markdown, para pessoas e para IAs
4. Uma IA também monta o manual (Explicaí Agent, via MCP)

**Regra fixa:** nunca citar nem comparar com concorrentes.

## 3. Público

Quem constrói ou mantém software e precisa entregar manual, sem time de documentação. Os três perfis têm o mesmo peso:

- Dev solo ou equipe pequena de SaaS
- Software house que entrega sistema para cliente
- Redator técnico ou analista de suporte

**Gatilhos que a comunicação nomeia:**
1. **Lançar:** o sistema vai para o ar sem manual.
2. **Entregar:** o cliente quer o manual junto.
3. **Atualizar:** a tela mudou e o manual ficou velho.

**Idioma:** bilíngue (PT-BR e EN) desde o primeiro dia.

## 4. Personalidade

**Arquétipo:** Sábio, no registro do *professor que você gostava*. Sabe muito e explica com clareza e paciência, com uma piada de vez em quando.

| Traço | É | Não é |
|---|---|---|
| Didático | uma coisa por vez, na ordem de uso | pedante, cheio de jargão |
| Paciente | não supõe que o leitor já sabe | condescendente |
| Preciso | cada passo funciona, cada marcador aponta certo | "mais ou menos isso aqui" |
| Aberto | código e processo à vista | mistério de startup |
| Bem-humorado na medida | uma tirada quando cabe | piada em todo botão |

## 5. Voz

| Canal | Registro |
|---|---|
| App, README, docs, site | formal, "você", imperativo, humor pontual só no site |
| Blog codesampa.io, redes | coloquial, primeira pessoa |

**Regras:** uma ideia por frase · voz ativa · o botão diz o que acontece · o erro diz o que houve e como resolver, sem desculpas · humor nunca em erro nem em passo de manual · sem hype ("revolucionário", "de ponta", "mágico", "potencializar") · nunca comparar com concorrentes · em inglês, humor mais contido.

**Tons dos manuais gerados (app e MCP):**

| Tom | Exemplo |
|---|---|
| Profissional (padrão) | "Clique em **Novo cliente** para abrir o formulário de cadastro." |
| Tranquilo | "Clica em **Novo cliente** e o cadastro abre na hora." |
| Personalizado | a pessoa descreve o tom em texto e a IA segue |

## 6. Narrativa

**História de origem oficial:**
> Todo sistema precisa de manual, e quase nenhum tem um bom. Fazer à mão leva dias: tirar print, marcar a tela, escrever cada passo, exportar, e refazer tudo quando a tela muda. O Explicaí faz esse trabalho braçal. É open source e gratuito porque documentar um sistema não pode custar mais que construí-lo.

Herói: quem constrói o sistema. Guia: o Explicaí.
